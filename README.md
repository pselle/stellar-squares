# Stellar Squares NFT Collection

[![Built with Stellar Scaffold](https://img.shields.io/badge/Built_with-Stellar_Scaffold-blue?style=for-the-badge)](https://stellarscaffold.org)
[![Powered by OpenZeppelin](https://img.shields.io/badge/Powered_by-OpenZeppelin_Smart_Contracts-green?style=for-the-badge)](https://github.com/OpenZeppelin/stellar-contracts)

**A showcase project demonstrating modern NFT development on Stellar using Stellar Scaffold, the Stellar Registry and OpenZeppelin contracts**

## 🎨 About

Stellar Squares is a generative art NFT collection inspired by Georg Nees' "Schotter" featuring geometric squares created through controlled randomness. This project serves as a complete example of:

- **Full-stack dApp architecture** built with [Stellar Scaffold](https://stellarscaffold.org)
- **Modern NFT development** using audited [OpenZeppelin Stellar contracts](https://github.com/OpenZeppelin/stellar-contracts)
- **Smart contract integration** with seamless frontend experience
- **Stellar Registry integration**: NFT collections are deployed from OpenZeppelin Wasm published in the [Stellar Registry](https://rgstry.xyz), and the gallery itself is published and found there by name

Each piece in the collection is a unique NFT generated by [algorithmic art](https://github.com/pselle/schotter-squares), showcasing the intersection of code, mathematics, and visual aesthetics on the Stellar blockchain.

## ✨ Features

- 🖼️ **NFT Gallery**: Browse and discover unique generative art pieces
- 💳 **Direct Purchase**: Buy NFTs directly from the gallery with wallet integration
- 🔗 **Multi-wallet Support**: Connect with various Stellar-compatible wallets
- 🎲 **Generative Art**: Each NFT is uniquely generated using controlled randomness algorithms
- 🔒 **Audited Contracts**: Built on OpenZeppelin's battle-tested smart contracts
- 🚀 **Live on testnet**: published in the Stellar Registry as `unverified/squares-gallery`

## 🏗️ Architecture

This project demonstrates a complete NFT gallery built on Stellar:

- **Frontend**: React + TypeScript with Vite, featuring wallet integration and responsive design
- **Smart Contracts**:
  - `squares-gallery`: deploys NFT collections and sells their tokens for XLM
  - OpenZeppelin `oz/nft-standard`, from the Stellar Registry, for each collection
- **Blockchain**: Stellar network with native asset (XLM) integration
- **Deployment**: Vercel with automated CI/CD via GitHub Actions

## 🚀 Developer Quick Start

### Prerequisites

- [Rust](https://www.rust-lang.org/tools/install). The toolchain and the `wasm32v1-none` target are pinned in `rust-toolchain.toml`
- [Node.js & npm](https://nodejs.org/en/download/package-manager) (v22 or higher)
- [Stellar CLI](https://developers.stellar.org/docs/tools/cli/install-cli)
- [Stellar Scaffold CLI plugin](https://stellarscaffold.org/docs/quick-start): `cargo install --locked stellar-scaffold-cli`
- [Stellar Registry CLI plugin](https://stellarscaffold.org/docs/registry): `cargo install --locked stellar-registry-cli`
- [Docker](https://docs.docker.com/get-docker/), only for running a local network

The gallery contract generates its NFT client from the Stellar Registry at build time, so every contract build needs a default network and identity that can reach the Registry:

```bash
stellar network use testnet
stellar keys generate my-key --network testnet --fund   # skip if you already have an identity
stellar keys use my-key
```

Then clone and install:

```bash
git clone https://github.com/pselle/stellar-squares.git
cd stellar-squares
npm install
```

### Option 1: Run the app against testnet

The quickest way to see the app. It uses the gallery already deployed on testnet, with no Docker and no deploys:

```bash
stellar scaffold build --build-clients --network testnet   # generate the contract clients
npm exec --workspace app -- vite --mode staging
```

### Option 2: Develop against a local network

1. **Start a local network and fund an account on it:**

   ```bash
   cp app/.env.example app/.env
   stellar container start local
   stellar keys generate squares-dev --network local --fund
   ```

   On a freshly started network, funding can fail for a minute while Friendbot starts up. Retry with `stellar keys fund squares-dev --network local`.

2. **Fetch the NFT Wasm and upload it to the local network.** The gallery deploys each collection from OpenZeppelin's `nft-standard` Wasm, and a fresh local network does not have it yet:

   ```bash
   mkdir -p target/stellar/local
   stellar registry download oz/nft-standard --version 0.7.2 --network testnet \
     -o target/stellar/local/oz__nft_standard_0_7_2.wasm
   stellar contract upload --wasm target/stellar/local/oz__nft_standard_0_7_2.wasm \
     --network local --source-account squares-dev
   ```

   The returned hash should match the `nft_wasm_hash` in `scaffold.yml`. Saving the file at that path also lets local contract builds find the Wasm without contacting the Registry. Repeat this step after `cargo clean` or after restarting the local network.

3. **Start the dev loop:**

   ```bash
   npm start
   ```

   This builds and deploys both contracts to the local network, generates the TypeScript clients, and serves the app. Contract changes are rebuilt and redeployed as you save.

4. **Have the gallery deploy a collection.** In a second terminal, once the contracts are deployed:

   ```bash
   npm run seed:local
   ```

   This deploys a 20-square collection at 10 XLM each. Run it once per fresh deployment.

Either way, the application is available at `http://localhost:5173`.

## 📦 Deployment

### Contract Deployment

The gallery contract is published to and deployed from the [Stellar Registry](https://rgstry.xyz) under the name `unverified/squares-gallery`. `scripts/registry.sh` wraps the `stellar registry` commands:

```bash
scripts/registry.sh testnet publish      # build and publish the Wasm (add --dry-run to simulate)
scripts/registry.sh testnet deploy       # first time: deploy the named gallery
scripts/registry.sh testnet register C…  # or: name a gallery that is already deployed
scripts/registry.sh testnet collection   # first time: deploy the Stellar Squares collection
scripts/registry.sh testnet upgrade      # later: upgrade the gallery to the latest published Wasm
scripts/registry.sh testnet id           # print the gallery's contract ID
```

The published version comes from `version` in `contracts/squares-gallery/Cargo.toml`, and each publish needs a higher version than the last. After the first deploy, set the contract ID as the gallery's `source` for that network in `scaffold.yml`, so the app's generated client points at it. Upgrades keep the same ID. Use `mainnet` in place of `testnet` for production.

### App Deployment

The app is a static build deployed to Vercel by GitHub Actions. Every push to a branch gets a preview deployment, and every push to `main` updates the live site. Both are built with `npm run build:staging`, so both point at testnet.

To deploy by hand, mirror what the workflows do:

```bash
npm run build:staging
rm -rf dist && cp -r app/dist dist
npx vercel build          # add --prod for production
npx vercel deploy --prebuilt   # add --prod for production
```

## 🔮 Stellar Registry Integration

This project uses the [Stellar Registry](https://rgstry.xyz), an on-chain registry of named, versioned contract Wasm.

- **NFT collections come from the Registry**: the gallery deploys each collection from OpenZeppelin's `oz/nft-standard` Wasm, pinned to version 0.7.2.
- **Typed client at build time**: `contracts/squares-gallery/src/nft.rs` uses `stellar_registry::import_contract_client!` to generate the NFT client from that published Wasm, so no Wasm file is checked in.
- **The gallery is published and deployed by name**: `scripts/registry.sh` publishes the gallery Wasm as `unverified/squares-gallery` and deploys or upgrades the named instance. See [Contract Deployment](#contract-deployment).

## 🛠️ Development

### Available Scripts

- `npm start` - Start the dev loop: contract watching, client generation and Vite
- `npm run seed:local` - Have the local gallery deploy a collection
- `npm run build` - Type-check and build the app with the settings in `app/.env`
- `npm run build:staging` - Generate the testnet clients and build the app for testnet
- `npm run lint` - Lint the app
- `npm run format` / `npm run format:check` - Format with Prettier, or check formatting
- `npm run test:e2e` - Run the Playwright smoke tests against testnet (build the staging clients first)
- `cargo test` - Run the contract tests

### Project Structure

```
├── contracts/              # Smart contracts (Rust)
│   ├── squares-gallery/    # Gallery contract: deploys collections, sells squares
│   └── nft-sequential-minting/  # Example NFT contract, used to generate the app's NFT client
├── app/                    # React frontend
│   ├── public/             # Static assets
│   └── src/
│       ├── components/     # UI components
│       ├── hooks/          # React hooks for blockchain integration
│       ├── pages/          # Application pages
│       └── providers/      # Context providers (wallet, etc.)
├── app-lib/                # Shared wallet, network and formatting helpers
│   └── clients/            # Generated contract TypeScript clients (not committed)
├── e2e/                    # Playwright smoke tests
├── scripts/registry.sh     # Publish, deploy and upgrade through the Stellar Registry
├── scaffold.yml            # Stellar Scaffold config: networks, accounts, contracts
└── AGENTS.md               # Guidance for AI coding agents
```
